# _Aleph 笔记知识库

一个基于 Typora + Git 的个人知识管理（PKM）库，遵循「输入 → 加工 → 输出」三层结构

## 二、笔记分类体系

### 2.1 输入层（他人内容）

- `book-@`：读书笔记——「模型提取 + 概念框架」（作者的观点）
- `ref-`：外部参考——文章 / 视频 / 资料的方法与观点

### 2.2 加工层（合成产物）

- `toolkit-@`：多个模型/概念合成的**可用新工具**——能在具体场景"想用就拿出来用"
- `card-@`：单一概念的稳定结晶——知识的最小单元；含核心定义 + 一张可视化或对比 + ≥2 个 book/ref 链接

`toolkit-@` 与 `card-@` 的差别：toolkit 是**多概念合成**（如"贝叶斯+斯多葛+反思 = 行动前/中/后三层决策"）；card 是**单概念结晶**（如"精度操控三型：锁死/通胀/坍塌"）。

### 2.3 过程层（持续追踪）

- `tracking-@`：行动 / 状态 / 实践追踪——持续更新，**不依附某本书**（按书做容器是反模式，已废弃）
- `movie-@`：观影笔记

### 2.4 自我认知层（`!` 前缀）

`!` 前缀底下是「我自己的东西」——我提的问题、我押的假设、我自己蒸出来的版本；对应 `_inbox / _overview / _todo` 的 `_` 前缀（被动基础设施）。ASCII 里 `!` 排在所有字母之前，所以这一层永远在文件树最顶部。

- `!q-`：当前真实存在的认知摩擦、问题或困惑
- `!h-`：基于一个或多个 `!q-` 形成的阶段性假设 / 解释 / 猜想
- `!distill-`：从多篇 card / book / moc 归纳合成、我自己一个字一个字敲出来的那一版（2026-08-29 立）

**`!q-` / `!h-` 的核心规则**：

- 二者不是线性升级关系，而是**循环关系**：`!q- → !h- → 新的 !q- → 修正 / 替换 !h-`
- `!h-` 只是暂时压缩问题的工作模型，**绝不代表问题已经得到解决**

**`!distill-` 是什么**（2026-08-29 由 PWPE 与 Ni-Te-audit 两个样本提取）：

| 判据 | 说明 |
|---|---|
| 方向 | 「归纳优先」——从多篇已有笔记合成、产出中心论点，反而生出新的 `!q-`；与 `!h-`（问题优先，`!q-` 的下游）方向相反 |
| 必须有厚版原件 | 蒸馏要先有原液。厚版是和 AI 一起长出来的探索记录，定稿后移入 `docs/archive/`；`docs/` 里只留蒸出来的这一版 |
| 必须自己写 | AI 能拆的只有它自己的脚手架（来源声明 / 接口索引 / 造的比喻词）；内容的读薄跑不了自己一个字一个字敲——AI 一简化它自己的代写，出来还是它的理解。**所以这个动作不可能外包，前缀本身就是署名** |
| 产出一句话 | 每篇收在一句中心论点上（如「决策的本质是大脑在非对称模型中做权衡——收益 vs 成本」） |

现有两篇：`!distill-PWPE与非对称决策模型`（厚版＝已归档的 `moc-@认知链路-v2`）、`!distill-Ni-Te-audit`（厚版＝已归档的 `书接上回-能力圈勘定`）。

判它是不是 `!distill-`：**先问有没有厚版原件**。没有厚版、直接写出来的，多半是 card（单概念）或 toolkit（多概念合成新流程）；有厚版但还没自己重敲一遍的，那是厚版本身，不算。

**何时建一条 `!q-`**（触发情境）：

- 一个问题让我反复回避 / 卡顿，需要借助 AI 才能勉强复述
- 文献里读到一个观点让我**不安 / 反感 / 不完全认同**，但说不清原因
- 同一个困惑在 2 篇以上笔记里冒过头，已经从 inbox 升级出来
- 最低门槛：能写出 1 句"锚点句" + 至少 1 组"张力"

**何时不建**（边界条件）：

- 问题查一下就有答案 → 不建，直接搜 / 链接到现成 card
- 问题已经在某个 card / toolkit 里有解 → 不建，引用它
- 仅仅是"暂时不知道"、还没卡过 → 留 `_inbox`，不升级
- 单纯想抒发 / 吐槽 → 不属于认知摩擦，留 inbox 或不写

**升级与归档**：

- `!q-` (status: seed) → 反复回访 + 形成临时假设 → 起 `!h-`
- `!q-` (status: stable) + 新证据 → 修改或推翻对应 `!h-`
- `!q-` 三个月没动 + 不再卡顿 → 归档到 `docs/archive/`

### 2.5 导航层（不是笔记，是地图）

导航层内部分三种，判据是**打开它时你在做什么动作**（2026-08-29 audit 拆开，此前笼统混在 `moc-@` 一类里）：

| | 判据 | 打开它是为了 | 现有 |
|---|---|---|---|
| `moc-@` 问题导航 | **有驱动问题**，且这个问题在推动下一步做什么 | 找路：我从哪进、走到哪去 | `moc-@沟通` / `moc-@人性矩阵` / `moc-@理性思考模型总结` / `moc-@INTJ人生指南` |
| dashboard 状态表 | **无驱动问题**，记的是现状与下一步 | 对表：我现在在哪，接下来该做什么 | `moc-@健康`（一个生活域）/ `_todo` §2.2 开着的问题 / `_toRead` 待读清单|
| 索引 | **无驱动问题**，记的是一个东西在多处的样子 | 查找：这个概念在哪些笔记里出现过 | `moc-@九大模型应用索引`（一个模型在多本书里长什么样）|

三条边界说明：

- **dashboard 和索引的差别**：dashboard 记「状态」，会过期、要维护；索引记「对照」，只随新笔记增补。`_models`（模型清单）2026-07-27 归档是因为它与 `_overview` 冗余，不是因为它是索引——`moc-@九大模型应用索引` 做的是跨书对照，`_overview` 没这功能，所以留着。
- **`moc-@人性矩阵` 是 moc 不是 dashboard**（2026-08-29 订正 08-02 的判定）：它的驱动问题「哪些节点还没对应到我的认知体系」在推动下一本读什么书，是缺口表不是状态记录。
- **`moc-@INTJ人生指南` 别被拉平**：它有驱动问题（「我无法改变他人，但可以改变自己」），且带四阶段 / 反 pattern / 元层风险——是这个库的用户手册，比一般 moc 重。

文件名前缀暂不动（改名会牵动大量链入，收益不抵成本）；类型写在 frontmatter `type` 字段里。

- `_overview.md`：知识库总索引（cluster + 导航层全景）

> 暂不纳入图中：`movie-@`（仅 1 篇，价值路径独立）、`!q-` / `!h-` / `!distill-`（自我认知层，与主流转独立运行）。
>
> 这一层与主流转的关系值得单说一句：`!distill-` 的原料就来自加工层（card / toolkit）与输入层（book / ref），但它不回流到 cluster——它归到 `!` 底下，因为判据是「谁写的」而不是「讲什么」。

读图三件事：

1. **cluster 是中心**（黄色高亮，三条 `--*` composition 实线汇聚）——输入 / 加工 / 过程三层的内容笔记都"归簇"到这里，cluster 是知识库的引力中心。
2. **加工层是枢纽**（三条 `..>` dependency 虚线指向）——输入层提取到这里、过程层反馈到这里、导航层链接到这里。
3. **两条独立通路汇入 Overview**：cluster（物理归簇）和 moc（问题导航）是 `_overview.md` 的两张并列总览表。

## 三、cluster 与 moc

笔记的两种组织方式，**不在同一个轴上**：

- **cluster（簇）** = 静态聚类，回答"这些笔记讲的是同一类东西"。例：所有沟通类笔记是一个 cluster。cluster **没有独立文件**，只在 `_overview.md` 中以章节形式存在。
- **moc（Map of Content）** = 问题导航地图，回答"我从哪里进、走到哪里去"。一张 moc 必须有一个**驱动它存在的问题**。

判断要不要建 moc：

- ✅ 有一个反复出现、跨多个 cluster 的问题——例：`moc-@认知链路` 串了贝叶斯 / 自由能 / 多巴胺 / 基因，回答"人是怎么决策的"
- ❌ 只是把同主题笔记列出来——这是 cluster，不需要 moc 文件
- ❌ 状态追踪表（如 `moc-@健康` 的最后更新表）——这是 dashboard，不是导航（三者判据见 §2.5）
- ❌ 一个概念在多本书里的对照（如 `moc-@九大模型应用索引`）——这是索引，不是导航

**默认姿势**：先有问题，再造 moc。cluster 只是物理归簇；moc 是被问题召唤出来的路径。

### `moc-@` vs `toolkit-@` 边界

容易混淆，差别抓一句话：

- `moc-@` 只**链接**——内容是"X 笔记讨论 Y" + 链接 + 上下文，没有新合成
- `toolkit-@` 是**合成产物**——把 N 个模型组合成 1 个可用的新工具流程

如果你写的内容**没有新合成**，只是串联和导航——那是 moc。如果你写的内容**有可使用的新工具流程**——那是 toolkit。

### 3.1 类型判定决策树

新内容来了不知道是哪种？走这张图：

```mermaid
flowchart TD
    start([新内容来了])
    start --> q1{"来源是什么？"}

    q1 -- "一本完整书" --> book["book-@"]
    q1 -- "文章 / 视频 / 二手资料" --> ref["ref-"]
    q1 -- "我自己产生的内容" --> q2

    q2{"我做了什么？"}
    q2 -- "我试过、有反馈" --> tracking["tracking-@"]
    q2 -- "我在合成模型" --> q3

    q3{"合成的形态？"}
    q3 -- "单个概念结晶" --> card["card-@"]
    q3 -- "多概念组合成新流程" --> toolkit["toolkit-@"]
    q3 -- "只串联、没新合成" --> q4

    q4{"有驱动问题吗？"}
    q4 -- "有，跨多个 cluster" --> moc["moc-@（建文件）"]
    q4 -- "没有，只是同主题" --> cluster["cluster（不建文件，进 Overview 章节）"]
```

> 未在图中：`movie-@` 走文学价值路径独立处理；`!q-` / `!h-` / `!distill-` 见 §2.4——那一层的判据是「谁写的」，不走这张按来源与形态分的树。

每个分支正好处理一个易混边界：

- **q1**：`book` vs `ref` ——完整作品 vs 二手摘要
- **q2**：`tracking` vs 合成产物——有反馈 vs 在做合成
- **q3**：`card` vs `toolkit` vs `moc`——单概念结晶 / 多概念合成 / 只链接不合成
- **q4**：`moc` vs `cluster` ——有驱动问题就建文件，否则只在 Overview 列章节

## 四、统一字段结构

每条笔记建议包含以下字段：

- `title`：标题
- `type`：book / ref / tracking / toolkit / card / moc / dashboard / 索引 / movie / q（认知摩擦，文件前缀 `!q-`）/ h（阶段性假设，文件前缀 `!h-`）/ distill（自己蒸出来的那一版，文件前缀 `!distill-`）
- `coreConcepts`：本笔记的核心模型或关键词列表
- `source`：原始来源或书名 / 作者（toolkit / card 类填"提炼自哪条 tracking 或 book"）
- `appliedModels`：tracking 列出应用的模型；book/ref 列出可应用的模型
- `actionItems`：可直接落地的行动或实验
- `links`：关联笔记，如 `book-@...` / `ref-...` / `toolkit-@...` / `card-@...` / `tracking-@...`
- `comment`：当前状态、疑问、补充说明
